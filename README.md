## Description

Planify is a Next.js (App Router) application that generates personalized travel itineraries. Users complete a short onboarding flow (who's traveling, route, dates, preferences, budget) and Planify uses the Perplexity API to research activities, restaurants, and hotels, then returns a structured, day-by-day itinerary rendered in a polished UI.

This repository contains the full client UI, onboarding flow, an Edge API route that constructs prompts and calls Perplexity, plus client-side caching and UI components to display generated itineraries.

## Key Features

- Guided onboarding flow (Name → Travelers → Destinations → Dates → Preferences → Budget → Summary)
- AI-driven itinerary generation using Perplexity (search + LLM prompt) via server-side Edge route
- Structured itineraries with morning/afternoon/evening activities, meals, hotels, and transport suggestions
- Car journeys produce `journey_stops`; flights/trains/buses include `transport_bookings`
- Client-side deterministic caching in `localStorage` (30-day expiry)
- Responsive, animated UI with reusable components (DayCard, HotelCard, JourneyStops, TransportBookings)
- Graceful loading/error/streaming states and retry flows

## Getting Started

### Prerequisites

- Node.js 18+ (recommended)
- npm (or yarn / pnpm)
- A Perplexity API key

### Installation

```bash
npm install
```

### Running locally

```bash
# Start local dev server
npm run dev

# Build for production
npm run build

# Start production server
npm run start

# Lint
npm run lint
```

Open http://localhost:3000 to view the app in development.

## Environment Variables

Create a `.env.local` in the project root. Example:

```env
# .env.example
PERPLEXITY_API_KEY=your_perplexity_api_key_here
```

- `PERPLEXITY_API_KEY` — required by the Edge API route at `app/api/generate-itinerary/route.ts`. Keep this secret and set it in your hosting environment (Vercel, Netlify, etc.) for production.

## Project Structure (high level)

- `app/` — Next.js App Router pages and API routes
  - `app/page.tsx` — Landing / marketing page
  - `app/onboarding/` — Onboarding flow entry and UI
  - `app/planner/` — Planner UI that loads/generated itinerary
  - `app/api/generate-itinerary/route.ts` — Edge API: builds prompts, queries Perplexity, returns JSON
- `components/` — UI components (onboarding steps, planner cards, UI helpers)
- `lib/` — Core logic
  - `lib/services/perplexity.ts` — Perplexity API wrapper

  - `lib/utils/cacheUtils.ts` — `localStorage` caching helpers

  - `lib/types/` — TypeScript models for onboarding & itinerary
- `assets/`, `public/` — static assets & Lottie JSON files
- `package.json` — project scripts and dependencies

## Features in Detail

- Onboarding Flow
  - Multi-step UI collects name, travelers, departure & destination, dates, preferences, and budget.
  - Data saved to `localStorage` and used to seed itinerary generation.

- Itinerary Generation Pipeline
  - Client posts onboarding data to `/api/generate-itinerary`.
  - API route builds three Perplexity search queries (activities, restaurants, hotels) using `buildSearchQuery` and then composes a large LLM prompt via `buildItineraryPrompt`.
  - Perplexity responses are combined and the LLM is asked to return strict JSON matching the `ItineraryResponse` shape from `lib/types/itinerary.ts`.
  - The server attempts to clean/parse the returned JSON and sends it to the client.

- Client UI & Caching
  - Planner (`app/planner/page.tsx`) attempts to read a cached itinerary first (key generated by `generateCacheKey`) and falls back to calling the API.
  - Successful generation is saved to `localStorage` with a timestamp. Cache entries older than 30 days are purged automatically.

## What’s Not Implemented (yet)

- Authentication / user accounts — no server-side user persistence. Onboarding + itineraries are stored in `localStorage` only.
- Persistent server storage for itineraries (database)
- PDF export, calendar export (iCal / Google Calendar), or direct booking engine flows
- Map integration (Mapbox / Google Maps)
